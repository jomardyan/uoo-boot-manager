BitLocker and encrypted disks

Have your recovery key before changing boot settings on an encrypted system.

Disk encryption is designed to refuse to unlock a drive when it cannot trust the boot process. Some boot changes therefore make Windows ask for a recovery password or leave a Linux volume waiting for a passphrase. Without that secret your data stays locked. Prepare it before you change anything.

Windows: BitLocker

Microsoft lists, among the causes of BitLocker recovery, changes to the boot manager, turning off or clearing the TPM, firmware or Secure Boot updates, changes that alter the TPM's platform measurements, and (on TPM 1.2 devices) changing the firmware boot order. On UEFI systems with Secure Boot, BitLocker can correct some boot configuration (BCD) settings without a recovery event, so not every edit triggers a prompt. You cannot rely on that for a given change.

1. Find your recovery password

  • Personal devices: sign in at account.microsoft.com/devices/recoverykey.
  • Work or school devices: your organization stores it in Microsoft Entra ID or Active Directory; ask your administrator.
  • On the PC, in an administrator terminal: manage-bde -protectors -get C: lists the numerical password. A printout or a saved text file also works.

The password has 48 digits. Keep a copy on a different device, not on the encrypted drive.

2. For a planned change, suspend protection

Suspend-BitLocker -MountPoint "C:" -RebootCount 1

Suspending leaves the drive encrypted. Protection resumes after the restart count you set (here, one restart), and resuming reseals the key without asking for the recovery password. Make your boot change, restart once, then confirm with manage-bde -status C:. Uoo does not suspend BitLocker for you.

3. If Windows asks for the key anyway

Enter the 48-digit password. Once Windows starts, you can suspend and resume protection to reseal the key for the new configuration.

Linux: LUKS

  • Make sure you know a working passphrase or have a recovery key. If a TPM unlocks the disk automatically, keep the fallback passphrase too.
  • Back up the volume header to storage that is not on the encrypted disk: sudo cryptsetup luksHeaderBackup /dev/<partition> --header-backup-file <file>. Protect that file like a key; it is not a way to recover a forgotten passphrase.
  • Uoo disables some GRUB features (such as saved selection) on encrypted boot layouts it cannot verify, and explains why.

Dual boot

Avoid changing the Secure Boot state or the firmware boot order while BitLocker is active unless you suspend it first. Reports from dual-boot users show that a changed boot chain can also prompt for the key on some systems; this is community experience, not a guarantee in either direction.
