Dual-boot troubleshooting

The most common dual-boot problems, why they happen, what Uoo does, and what you can do yourself.

These are the problems dual-boot users report most often, with what Uoo's Dual boot page can fix, what it only reports, and what you must do yourself. The causes come from vendor documentation and community reports linked in each section; hardware varies, so treat the community items as leads, not guarantees.

  • Windows is missing from the GRUB menu
  • The GRUB menu never appears
  • The firmware forgets or ignores the Ubuntu entry
  • Windows asks for a BitLocker recovery key
  • A Windows drive is read-only or will not mount in Linux
  • The clock is wrong after switching systems
  • The EFI System Partition is full
  • efibootmgr says "No space left on device"
  • UEFI variables are read-only or unsupported
  • Legacy BIOS and UEFI are mixed
  • Secure Boot errors and the 2026 certificate change
  • Linux cannot see the disk (Intel RST/VMD)

Windows is missing from the GRUB menu

You see: GRUB lists Ubuntu but not Windows, and update-grub prints that os-prober will not be executed.

Why it happens: GRUB's tool for finding other systems, os-prober, is disabled by default since GRUB 2.06 (Ubuntu 22.04 and later). It also cannot see Windows when Windows' EFI partition is not mounted or when it is on another disk.

What Uoo does: The Dual boot page adds a verified GRUB entry for Windows Boot Manager when its EFI partition is mounted, or turns on GRUB_DISABLE_OS_PROBER when it is not. It tells you which later GRUB file overrides the setting if one does, and names unmounted EFI partitions.

What you can do: Manually: set GRUB_DISABLE_OS_PROBER=false in /etc/default/grub, install os-prober if needed, and run sudo update-grub. BitLocker does not hide Windows' boot files from this check.

Sources: OMG! Ubuntu · It's FOSS

The GRUB menu never appears

You see: The computer starts Windows straight away, or Ubuntu starts without a menu.

Why it happens: Either Windows Boot Manager comes first in the firmware boot order (Windows updates and firmware resets often put it there), or GRUB is set to hide its menu (GRUB_TIMEOUT_STYLE=hidden or a timeout of 0).

What Uoo does: Fix dual boot can show the menu and put Ubuntu's entry first, after a backup. On a BitLocker system it leaves the reordering unselected, because starting Windows through GRUB can change what the TPM measures.

What you can do: Run efibootmgr to see the order, or use the Firmware page. You can also pick Ubuntu once from the firmware boot menu (often F12 or Esc) without changing anything.

Source: linux.org thread (community)

The firmware forgets or ignores the Ubuntu entry

You see: Ubuntu is missing from the boot menu after a firmware update, or an entry you created vanishes at the next restart.

Why it happens: Some firmware drops boot entries it did not create, and some only trusts a loader at EFI/BOOT/BOOTX64.EFI. Community reports describe both behaviors.

What Uoo does: Fix dual boot registers Ubuntu's loader in the firmware again and tells you when no fallback loader exists.

What you can do: If the entry disappears again, install a fallback loader with sudo grub-install --removable (Uoo does not do this for you), or keep using the firmware's own boot menu. Updating the firmware can help.

Source: Qubes OS forum thread (community)

Windows asks for a BitLocker recovery key

You see: A blue recovery screen appears after you change the boot order, Secure Boot, firmware, or start Windows through GRUB.

Why it happens: BitLocker with a TPM releases its key only when the boot chain matches what it was sealed to. Microsoft lists changes to the boot manager, the TPM, firmware and the platform measurements among the causes. Windows 11 24H2 can also turn on device encryption by itself, so you may not know it is active.

What Uoo does: Uoo asks you to confirm you have the recovery password, keeps your boot order when registering Ubuntu, and leaves 'Ubuntu first' unselected. It never suspends or changes BitLocker.

What you can do: Find your key first (encrypted disks guide), suspend protection for planned changes, and check manage-bde -status C: in an administrator terminal to see whether C: is encrypted.

Sources: Microsoft Learn · Tom's Hardware · Phoronix

A Windows drive is read-only or will not mount in Linux

You see: Linux reports that the NTFS volume is in an unsafe state or mounts it read-only.

Why it happens: Windows Fast Startup (hybrid shutdown) leaves the volume hibernated instead of cleanly closed.

What Uoo does: Reports the problem. On Windows it checks whether Fast Startup is on. It does not change the setting or touch the volume.

What you can do: Shut Windows down fully (hold Shift while choosing Shut down) or turn off Fast Startup (powercfg /h off). Do not run ntfsfix on a Windows installation you still use.

Sources: Manjaro wiki · Linux Uprising

The clock is wrong after switching systems

You see: The time is off by your UTC offset after booting the other system.

Why it happens: Windows keeps local time in the hardware clock by default; Linux expects UTC.

What Uoo does: Reports it (on Windows it reads the setting). It does not change either system.

What you can do: Pick one fix: timedatectl set-local-rtc 1 on Linux, or set the RealTimeIsUniversal registry value to 1 on Windows. Do not do both.

The EFI System Partition is full

You see: Kernel or bootloader updates fail with 'No space left on device', or the installer refuses a small partition.

Why it happens: Windows often creates a 100 MiB ESP shared by every operating system. Some distributions store kernels on the ESP, which fills it quickly, while a traditional GRUB layout needs far less.

What Uoo does: Warns when less than 8 MiB is free on the mounted ESP. It does not resize or reformat anything.

What you can do: Keep kernels on the Linux filesystem rather than the ESP, remove only vendor folders you are sure are obsolete, or enlarge the ESP from a live session with a backup. Do not reformat an ESP that holds Windows' boot files.

Sources: openSUSE forum · Ubuntu Discourse (community)

efibootmgr says "No space left on device"

You see: Creating or changing a UEFI entry fails even though the disk has free space.

Why it happens: The firmware's variable storage (NVRAM) is full. Every boot entry uses a little of a very small store.

What Uoo does: Explains the error in plain language and rolls the change back.

What you can do: Delete clearly unused entries on the Firmware page (old systems, USB drives), then retry. Never edit files under /sys/firmware/efi/efivars by hand.

Source: GNU Guix bug report (community)

UEFI variables are read-only or unsupported

You see: efibootmgr reports a read-only file system, 'Operation not permitted', or that EFI variables are not supported.

Why it happens: The variable store is mounted read-only, a variable is protected, or the system started in legacy BIOS mode.

What Uoo does: Detects a read-only variable store and offers no firmware steps; failures are explained when they happen.

What you can do: Remount with sudo mount -o remount,rw /sys/firmware/efi/efivars, and make sure the system starts in UEFI mode.

Legacy BIOS and UEFI are mixed

You see: Ubuntu starts in legacy (CSM) mode, but Windows was installed in UEFI mode, so GRUB cannot start Windows.

Why it happens: BIOS-mode GRUB cannot boot a UEFI Windows. The two modes must match.

What Uoo does: Detects a legacy session on a disk with an EFI System Partition and tells you which direction to change.

What you can do: Switch the firmware to UEFI mode, then repair Ubuntu's UEFI loader from the Repair page. Converting Windows is much riskier and is not offered.

Secure Boot errors and the 2026 certificate change

You see: Linux stops with 'Verifying shim SBAT data failed' or a Secure Boot policy violation after a Windows update.

Why it happens: In August 2024 a Windows update applied a Secure Boot revocation that blocked unpatched Linux boot loaders on some dual-boot systems; Microsoft confirmed it. Separately, Microsoft's 2011 Secure Boot certificates expire in 2026 (June 24, June 27, and October 19). Existing systems keep booting, but updates add the 2023 certificates over time, and changing the Secure Boot database changes the TPM measurement (PCR 7).

What Uoo does: Notes the situation when Secure Boot is on and Windows is present. It never changes keys or Secure Boot.

What you can do: Keep Ubuntu's shim updated and have your BitLocker or LUKS recovery key ready before firmware or Secure Boot updates. For an SBAT error, update shim from a working session or follow your distribution's guidance; temporarily disabling Secure Boot is a last resort and needs the recovery key on BitLocker systems.

Sources: BleepingComputer · Microsoft Support · Red Hat

Linux cannot see the disk (Intel RST/VMD)

You see: The Ubuntu installer or a running system shows no NVMe drive, though Windows uses it.

Why it happens: Intel RST/VMD (RAID) mode hides the drive from Linux. Switching the firmware to AHCI makes it visible but can leave Windows unable to boot unless Windows was prepared first.

What Uoo does: Nothing: Uoo cannot manage a disk it cannot see.

What you can do: Disable VMD in the firmware if it offers the option, or prepare Windows for AHCI before switching. Back up first and follow your PC maker's documentation.

Sources: Ubuntu Discourse · Dell community (community)

Dual boot fix or Repair?

Use Dual boot for settings: menu, discovery, entries, and order. Use Repair when loader files are damaged or missing, for example when no EFI/ubuntu folder exists. Repair needs a typed confirmation and a supported layout.

⚠

Encrypted disk? Have your recovery key first.

Before changing boot settings on a BitLocker or LUKS system, find your recovery password or passphrase and keep a copy on another device. Read the encrypted-disk guide.
