Uoo on Ubuntu

A GTK4 and libadwaita desktop for Ubuntu's GRUB and UEFI boot configuration, with an authenticated helper.

Requirements

  • Ubuntu 24.04 or newer, GTK 4.6+, libadwaita 1.5+, Python 3.10+, and polkit. The Debian package installs these.
  • GRUB controls need an existing GRUB installation with update-grub and grub-script-check.
  • Firmware controls need UEFI boot mode and efibootmgr.
  • UEFI reinstallation needs Ubuntu's signed shim and GRUB packages; BIOS reinstallation needs grub-pc-bin.

What Uoo manages on Ubuntu

AreaWhat you can do
Boot menuGRUB default or saved selection, timeout, visibility, one-time boot.
EntriesManaged Linux and EFI chainloader entries; enable, disable, reorder, and remove them.
Boot optionsKernel arguments, recovery entries, OS discovery.
UEFI firmwareBoot order, inclusion, activation, next boot, local EFI registrations.
AppearanceGRUB graphics mode, colors, and a validated PNG background.
BackupsConfiguration snapshots, restore, and portable import and export.
Diagnostics and repairSupported Ubuntu UEFI and BIOS bootloader repair.

Where Uoo stores things

  • GRUB settings: /etc/default/grub.d/zz-uoo.cfg. Other GRUB settings are preserved.
  • Managed entries: /etc/grub.d/41_uoo.
  • Backups: /var/lib/uoo-boot-manager/backups (private).

Changes are serialized, journaled, verified, and rolled back if a tool fails. An unfinished transaction recovers before the next change. Direct editing of GRUB scripts is not exposed.

Limits

  • Ubuntu is the verified GRUB backend. Other distributions get the desktop, demo, and available inspection, but GRUB changes and repair are not established there.
  • Saved and one-time GRUB selection need a verified writable environment block. Unsupported RAID, LVM, encrypted, or checksumming boot layouts disable them; a separately mounted plain /boot can support them.
  • Bootloader repair currently supports verified x86-64 Ubuntu plain-disk layouts. Review the detected target and type it to confirm.
  • Backups cannot recover a failed disk or guarantee recovery from power loss before the app can run again.
  • AppImage, Flatpak, and Snap need the matching native host package for authenticated system operations.
  • The currently booted entry is protected, and at least one active firmware entry must stay in the boot order.

Full details: README on GitHub and Linux packaging.

⚠

Encrypted disk? Have your recovery key first.

Before changing boot settings on a BitLocker or LUKS system, find your recovery password or passphrase and keep a copy on another device. Read the encrypted-disk guide.
